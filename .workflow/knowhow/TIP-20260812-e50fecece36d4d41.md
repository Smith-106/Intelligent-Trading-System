When producing Maestro plan/plan-check JSON under a Run outputs/ directory, `_meta` may only contain kind, schema, and optionally role/alias.

Unrecognized keys (timestamp, source, planning_mode, plan_type, session_id, run_id, checker, round, plan_run, sources, etc.) cause `maestro run check` to reject the artifact as invalid _meta and block required gates (e.g. Produce plan / Validate plan schema) even if the file exists on disk.

Put provenance/extra fields outside `_meta` (body-level keys such as check_meta or design_decisions). Canonical examples: findings use `{kind,schema,role}`; plan uses `{kind,schema,role,alias}`.

Symptom: warnings "Expected outputs/plan.json was not produced" despite the file existing, plus errors listing Unrecognized keys under _meta.
